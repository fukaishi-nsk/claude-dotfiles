# nancoオンライン相談の当日準備（自動）

深石さんの指示（2026-11-05）:「この1連のフローをmaciminiのclaudecodeにスケジュール登録したい」。
元にしたのは 2026-11-05 に手で行った愛豊電機（蟹井さま）の準備。決めたこと（同日）:
- 実行は平日の朝 9:00、対象は**当日**の相談
- 対象は**オンライン相談の予約だけ**（既存顧客の定例・レディクル面談は対象外）
- 顧客フォルダが無い新規の方でも、Customers の行を作ってよい

この手順で行う書き込みは**事前承認済み**（範囲はこの手順書に書いたものだけ）:
Notion「nanco営業データ」へのページ作成、「🫂 Customers」の行の作成・更新、Slack `#nanco_カスタマーお問い合わせ` への投稿、`#log_fukaishi` への報告。
**メールの下書き・送信、Linear の起票、カレンダーの変更はしない。** 迷ったら書かずに `#log_fukaishi` で聞く。

## 1. 対象の相談を探す

- Google カレンダー（fukaishi@nsketch.com の primary）で**今日**の予定を取る
- タイトルが `[nanco]在庫管理アプリnanco オンライン相談 (` で始まり、status が confirmed のもの
- 予約者: description の「予約者:」の下の名前とメールアドレス
- 次のものは準備しない（報告に理由を書く）
  1. 予約者のアドレスが `@nsketch.com` / `@nanco.io`（社内のテスト）
  2. 予約者の responseStatus が declined
  3. nanco営業データに、今日の日付（`date:At:start` = 今日）でその相手のページが既にある（手で準備済み。二重に作らない）
  4. 相談の開始まで1時間を切っている（アプリが閉じていて実行が遅れたとき）
- 対象が0件なら、何も書かずに終わる（報告もしない）

## 2. 材料を集める（読み取りだけ）

`~/.claude/skills/nanco-meeting-prep/SKILL.md` の「2. 材料集め」に従う。最低限これを全部見る:

- **Gmail**: 予約者のアドレスと名前で `search_threads` → 見つかったスレッドは**全部 `get_thread`（PLAIN_TEXT）で読む**（search は1スレッド5件まで）。予約完了メール・予約のキャンセルと取り直し・先方の質問（ウェルカムメールへの返信、HubSpot など）・こちらの最後の返信・未返信の相手メールを確かめる。nanco の「更新まとめ」メール（件名 `【…の更新まとめ】<WS名> | nanco`）に予約者のアドレスが出ていれば、WS 名と更新された品目が分かる
- **社名**: 相手のメールの署名・本文で名乗った表記を使う。メールドメイン（gmail 等）や WS 名から推定しない。分からなければ「氏名さん」
- **顧客フォルダ**: 共有ドライブ `Nanco/カスタマー/` に社名・氏名を含むフォルダがあれば、KB（02_Plan）と 06_Recording の文字起こし全文、00_File_from を読む
- **Notion**: Customers DB（`collection://842d7d57-058d-4df8-a229-9cea0a2eadaf`）で社名・氏名を検索。前回の面談ページがあれば読む
- **Linear**（team `nanco`）: 社名・氏名で `list_issues`
- **nanco管理画面**: 実Chrome（claude-in-chrome）で `https://app.nanco.io/admin/workspaces?search=<予約者のアドレス>` → ID・WS名・ユーザー数・アイテム数・作成日・最終操作・Next Date を読む。社名でも引き直す。開けない・ログインが切れているときは「未確認」と書いて先へ進む（ログインはしない）。開いたタブは最後に閉じる
- **カレンダー**: Meet のリンク・出欠（姉崎さんの返事）・前後の予定との重なり

## 3. Notion の面談ページを作る

- 置き場所: 「nanco営業データ」`collection://1be60519-c341-4ee2-8c68-9db180f003ca`
- Name: `YYMMDD_nanco_<社名>`（社名が無ければ `YYMMDD_nanco_<氏名>さん`）、Status=`Not started`、`date:At:start`=今日、`date:At:is_datetime`=0
- 中身は `nanco-meeting-prep` の「3. ページの構成」どおり（思い出しメモ callout は必須）。書き方の注意もそのまま守る（推定・未確認の明記、メールアドレスは前後に半角スペース、他ページは mention）
- 料金は資料・メールにある数字だけ。複数 WS の料金のように資料に無いものは「当日その場で金額を約束しない」と書く

## 4. Customers の行

- 社名・氏名で行を探す（`notion-search` に `data_source_url` を付けて。表記ゆれに注意）
- **行がある**: `nanco-status-update` の決まりで、ボール=打合せ予定、期日=今日、現状・次のアクション・最終接触・確認日・根拠を更新する（memo は触らない）
- **行が無い**: 顧客フォルダが無くても作ってよい（2026-11-05 深石さん）。Proposal=社名（無ければ氏名＋「さん」）、どんな会社・窓口（分からない所は「未確認」）、ボール=打合せ予定、利用状況=ベータ版（WS があってトライアル中）か営業中（WS なし）、期日=今日、トライアル期限=管理画面の Next Date（読めなければ空欄）、最終接触、Started=WS 作成日（分かれば）、URL=署名の会社 URL、確認日=今日、根拠。経路は空欄
- 面談ページの「🫂 Customers」をその行に紐づけ、本文の Customers 行の欄に mention を入れる

## 5. 読み直す

面談ページを fetch して、表・callout・リンク・Customers の紐づけが入っていることを確かめる。崩れていたら直す。直せなければ報告に書く。

## 6. Slack で共有

`#nanco_カスタマーお問い合わせ`（C04S812EP1Q）に、相談1件につき1投稿。2026-11-05 の手動投稿の型:

```
<@U08ML5202> 今日 <HH:MM> のオンライン相談（<社名>・<氏名>さま）の準備ページです。
面談ページ: <URL>
Customers 行: <URL>

・要望: <先方の言葉に沿って1〜2行>
・WS「<WS名>」（<ID>）トライアル中・期限 <M/D>・アイテム<n>・ユーザー<n>

・<こちらがメールで約束していること。未着手ならそう書く>
```

- 一次情報に無い行は書かない（WS が無ければ「WS なし」）
- 姉崎さんが declined のときは、メンションのあとに「（カレンダーは欠席の返事）」と書く

## 7. 報告

Slack `#log_fukaishi`（C03119VSJGK）に1回の実行につき1投稿。先頭に `<@U02PBGQ62BB>`。
```
<@U02PBGQ62BB> 【相談準備】<実行日>
・準備した: <HH:MM> <社名や氏名>（面談ページ URL／Customers 行 新規 or 更新）
・準備しなかった: <HH:MM> <社名や氏名> — <理由>
・当日までに見ておくこと: <未返信メール・未着手の約束・出欠未回答・予定の重なり・未確認事項>
```
エラーで止まったときは、どこまでできてどこで止まったかを書いて投稿する。
