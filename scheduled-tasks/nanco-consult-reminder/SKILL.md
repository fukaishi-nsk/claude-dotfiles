# nancoオンライン相談のリマインド（自動送信）

深石さんの指示（2026-10-26）:「前日リマインドは自動で君送って」「月曜の相談は月曜の午前に送って。月曜の予約可能は13時以降にした」。
この手順で送るメールは**事前承認済み**（送る範囲はこの手順書に書いたものだけ）。迷ったら送らずに Slack で聞く。

## いつ・何を送るか

- 実行: **平日（月〜金）9:30**（cron `30 9 * * 1-5`）
- 対象の相談:
  - 月曜の実行: **今日（月曜）**の相談と、**明日（火曜）**の相談
  - 火〜木の実行: **明日**の相談
  - 金曜の実行: 明日（土曜）の相談（ふつうは無い）
- 相談の見つけ方: Google カレンダー（fukaishi@nsketch.com の primary）で、対象の日の予定のうち、タイトルが `[nanco]在庫管理アプリnanco オンライン相談 (` で始まり、status が confirmed のもの
- 予約者: 予定の description の「予約者:」の下の名前とメールアドレス。参加者の responseStatus が declined なら送らない

## 送らない場合（Slack の報告に理由を書く）

1. 予約者のアドレスが `@nsketch.com` / `@nanco.io`（社内のテスト）
2. 予定の作成日時（created）が実行日の当日（予約したばかりで、Google カレンダーの予約完了メールが届いたところのため）。前日以前の予約なら送る（2026-10-26〜 予約のお礼メールは送らない方針になったので、このリマインドが唯一の案内になる）
3. 実行日の前日0:00以降に、support@ か fukaishi@ から予約者のアドレスへ送ったメールが既にある（Gmail `to:<アドレス> in:sent after:<前日>` で探し、見つかったら送らない。その返信がリマインドを兼ねている）
4. 予定の説明やスレッドから、相談が取り消し・変更になっていると読める
5. 下のどこかで、確かめた値が食い違ったとき
6. アプリが閉じていて実行が遅れたとき: 当日の相談は開始まで2時間を切っていたら送らない。前日の相談は、実行時刻が前日の19:00を過ぎていたら送らない（どちらも Slack で知らせる）

## 文面（この型だけを使う。足さない・削らない）

前日の場合:
```
<宛名1行目>
<宛名2行目>

在庫管理アプリnancoサポートです。
明日のオンライン相談の件、リマインドです。

<M>月<D>日（<曜>）<HH:MM>〜<HH:MM>、以下のリンクからご参加ください。
<MeetのURL>
ご都合が悪くなった場合は、カレンダーの予約をキャンセルのうえ、別の日程でご予約ください。

ひきつづき、よろしくお願いします。
+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+-
はじめやすい、続けやすい在庫管理アプリ「nanco」
https://nanco.io
```
月曜当日の場合: 「明日のオンライン相談の件」→「**本日の**オンライン相談の件」、日時の行の頭に「**本日**」を付ける（例「本日10月26日（月）13:00〜14:00、以下のリンクからご参加ください。」）。ほかは同じ。

- 宛名: support@ から予約者のアドレスへ最後に送ったメールの、冒頭の宛名の行（社名＋「〇〇さま」）をそのまま使う。送ったことが無ければ、予約名＋「さま」の1行だけ（社名は書かない。ドメインから推定しない）。予約名が会社名・部署名（「株」「㈱」「部」「課」などを含む）なら、1行目に予約名、2行目に「ご担当者さま」
- 時刻は予定の start・end（日本時間）。曜日は日本語1字
- Meet の URL は予定の conferenceUrl（`?hs=` などは付けない）
- 同席者・トライアル期限・当日の議題・取り込みの進み具合などは**書かない**

## 送り方

1. 返信先を決める: 予約者のアドレスを含むスレッドのうち、いちばん新しいもの（get_thread で全件を見る。search の一覧だけで決めない）の、最後のメッセージの id。やりとりが予約完了メール（件名「予約が完了しました: [nanco]…」・差出人 fukaishi@）しかないなら、その予約完了メールの id
2. 本文を HTML で書く（改行は `<br>`、URL は `<a href="…">…</a>`。`&lt;br&gt;` のようにエンティティ化しない）
3. 下書きを作る:
   `python3 -W ignore ~/claude-dotfiles/scripts/gmail_draft.py create --from support@nanco.io --to <予約者> --cc anezaki@nsketch.com support@nanco.io --html-file <本文> --reply-to <1の id>`
   （CC は1つの `--cc` の後ろに並べる。返信先のメールに先方側の CC があれば、それも足す）
4. `gmail_draft.py show <draftId>` で From が `support@nanco.io`、To が予約者、threadId が1のスレッドであることを確かめる。違ったら送らず、下書きを残したまま Slack で知らせる
5. Gmail コネクタの `send_message` に `draftId` だけを渡して送る
6. 送信済みメッセージを開き（get_thread METADATA_ONLY で末尾の SENT を特定）、From が support@ であること、下書きが消えたこと（list_drafts `to:<予約者>`）を確かめる


対象の相談が1件も無い日は投稿しない。エラーで止まったときは、どこで止まったかを書いて投稿する。

- `~/claude-dotfiles/scripts/gmail_draft.py` と認証（`~/.config/claude-gmail/`）があること（MacBook・Mac mini とも導入済み・2026-10-19）
- Gmail・Google カレンダー・Slack のコネクタが使えること
- 実行時刻の登録はPCごと。**登録は1台だけ**（二重に送らないため）
