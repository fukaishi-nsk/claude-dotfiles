## ボールの基準（要点）
会話の上で次に動くのは誰か。こちら（深石／姉崎）＝先方がこちらの返信・成果物を待っている。先方＝こちらが最後に送り、先方の返事・行動待ち。打合せ予定＝次の打合せ日が決まっている。様子見＝どちらも動かない。社内の NANCO タスクが残っているだけでは「こちら」にしない。「できたら連絡します」の約束は次のアクションに書く。

## 手順
1. `list_issues`（team `NANCO-CRM`、ページ送りで全部）を引き、本文に「## 最新の状況」があり、ボールが様子見以外のイシューを対象にする
2. 次のイシューを一次情報で確かめ直す
   - **毎朝**: 前回の実行（月曜は金曜朝）以降に動きがあった顧客。support@ が入ったメール一覧（`after:` で前回実行日以降）・#nanco_line の新着・team `nanco` の新規起票と根拠にある番号の状態変化から拾う（2026-10-22 の実行で確立したやり方）
   - **毎朝**: 期日（dueDate）を過ぎたもの、期日が今日・明日のもの
   - **木曜（定例前）だけ追加**: 確認日が7日より古いものの洗い直し
   - Gmail: 顧客ドメイン・社名でスレッドを探し、**get_thread で最後のメッセージの向きと中身を開いて**確かめる（スニペットで決めない）
   - Linear: 根拠にある NANCO- 番号を get_issue で引き直す（前回の報告からコピーしない）
   - LINE の顧客（そら植物園・GREENING・東京バルーン）は #nanco_line の転写を読む。GREENING 側の発言は転写されないので「未確認」とする
   - 会議があった顧客は、カレンダーと 06_Recording の文字起こしで確かめる
   - 数が多い（10社超）ときは、読み取りだけのエージェントを顧客グループごとに並列に走らせ、結果を受けて書き込みはこのセッションで行う
3. 変わったイシューだけ、`save_issue` の `patch` で「## 最新の状況」の節を置き換える（本文全体を送り直さない）。確認日（今日）と根拠は必ず更新する。期日は dueDate。ボールが変わったら、nanco-status-update の「ステータスの決め方」でステータスも合わせる（迷ったら変えない）。動いた内容を `save_comment` で1行残す
4. 判定に迷うものは書き換えず、報告で「要確認」にする
5. Slack に報告する（下の型）。報告前に、書き込んだイシューのうち数件を get_issue で読み直し、最新の状況と自動の記録の両方が残っていることを確かめる

## 報告の型（親メッセージは短く・詳細はスレッド）
親:
```
<@U02PBGQ62BB> 📋 nanco顧客 見直し M/D（木曜は「週次見直し M/D（定例前）」）
🔴 こちらボール: N社（深石 a・姉崎 b）／期日超過: M件
・[社名]（姉崎・CRM-◯◯）…1行（期日 M/D 超過）
・…
一覧: https://linear.app/nsketch/team/CRM/all
```
スレッドに: 今回更新したもの（社名・CRM番号・変えた欄・前→後）／今日・明日の打合せ／要確認のものと理由／トライアル期限が14日以内のもの（毎朝同じなら木曜だけ書く）／同じ会社に見えるイシューが2つあるもの／確かめられなかったこと。
こちらボールも期日超過もゼロなら、親は `🟢 こちらボール・期日超過なし` の1行にする。更新も要確認もない日は、スレッドを作らず親1通だけにする（毎朝の通知を増やしすぎない）。

## 権限（無人実行）
- 使うもの: Linear `NANCO-CRM` の「## 最新の状況」・期日・ステータスの更新とコメント、Gmail・team `nanco` の Linear・カレンダーは読み取りだけ、Slack は #log_fukaishi への投稿と各チャンネルの読み取り、Drive は読み取りだけ
- 使わないもの: Notion への書き込み（9:40 の写しに任せる）、メール・LINE の送信、下書き作成、team `nanco` の起票・更新、NANCO-CRM のイシューの作成・削除・統合、ボットの「## 自動の記録」の編集、カレンダーの変更、nanco 在庫の書き込み、削除系すべて
- Bash は読み取り系だけ（heredoc や複合コマンドは権限確認で止まる原因になったので避ける）
- 権限で拒否されたら止まらずに先へ進み、報告の最後に「⚠️権限スキップ」として書く
