## ボールの基準（要点）
会話の上で次に動くのは誰か。こちら（深石／姉崎）＝先方がこちらの返信・成果物を待っている。先方＝こちらが最後に送り、先方の返事・行動待ち。打合せ予定＝次の打合せ日が決まっている。様子見＝どちらも動かない。社内の Linear タスクが残っているだけでは「こちら」にしない。「できたら連絡します」の約束は次のアクションに書く。

## 手順
1. ボールが空欄でない行を、SQL で1回だけまとめて引く（Query Data Source にはワークスペースの利用上限がある。何度も叩かない。上限に達していたら notion-search ＋ notion-fetch で読み、報告に1回だけ書く）
2. 確認日が7日より古い行と、期日を過ぎた行を、一次情報で確かめ直す
   - Gmail: 顧客ドメイン・社名でスレッドを探し、**get_thread で最後のメッセージの向きと中身を開いて**確かめる（スニペットで決めない）
   - Linear: 根拠にある NANCO- 番号を get_issue で引き直す（前回の報告からコピーしない）
   - LINE の顧客（そら植物園・GREENING・東京バルーン）は #nanco_line の転写を読む。GREENING 側の発言は転写されないので「未確認」とする
   - 会議があった顧客は、カレンダーと 06_Recording の文字起こしで確かめる
   - 数が多い（10社超）ときは、読み取りだけのエージェントを顧客グループごとに並列に走らせ、結果を受けて書き込みはこのセッションで行う
3. 変わった行だけ `notion-update-page`（update_properties）で更新する。確認日（今日）と根拠は必ず更新する。memo 列・列の構成・選択肢には触らない。行は削除しない
4. 判定に迷う行は書き換えず、報告で「要確認」にする
5. Slack に報告する（下の型）。報告前に、書き込んだ行のうち数件を notion-fetch で読み直して値が入っていることを確かめる

## 報告の型（親メッセージは短く・詳細はスレッド）
親:
```
<@U02PBGQ62BB> 📋 nanco顧客 週次見直し M/D（定例前）
🔴 こちらボール: N社（深石 a・姉崎 b）／期日超過: M件
・[社名]（姉崎）…1行（期日 M/D 超過）
・…
一覧: https://app.notion.com/p/2ecb60a44ee84e88adc236122ccb9771
```
スレッドに: 今週更新した行（社名・変えた列・前→後）／要確認の行と理由／トライアル期限が14日以内の行／Notion の上限などで確かめられなかったこと。
こちらボールも期日超過もゼロなら、親は `🟢 こちらボール・期日超過なし` の1行にする。

## 権限（無人実行）
- 使うもの: Notion（search / fetch / query-data-sources / update-page）、Gmail・Linear・カレンダーは読み取りだけ、Slack は #log_fukaishi への投稿と各チャンネルの読み取り、Drive は読み取りだけ
- 使わないもの: メール・LINE の送信、下書き作成、Linear の起票・更新、カレンダーの変更、nanco 在庫の書き込み、削除系すべて
- Bash は読み取り系だけ（heredoc や複合コマンドは権限確認で止まる原因になったので避ける）
- 権限で拒否されたら止まらずに先へ進み、報告の最後に「⚠️権限スキップ」として書く

## 最後に
作業レポート（達成度％／確かめた社数・更新した社数・要確認の社数／次のアクション）をスレッドの末尾に1行で添える。
