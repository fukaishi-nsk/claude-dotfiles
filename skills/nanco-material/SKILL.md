# nanco-material — 顧客向け資料の改定

## 北極星（2026-10-19 深石さん指示）

- オンライン相談やレディクル案件の後に、相手に合わせて資料を改定して送ることが増える。**深石さんが手直しなしで送れる資料**を安定して出すのがゴール
- メールの文体（`/email-draft`）と同じく、**資料への添削・指摘は1件も取りこぼさず、その場でこのファイルに追記して型を育てる**。無修正で通った作り方も成功例として残す
- 正本は `~/claude-dotfiles/skills/nanco-material/SKILL.md`（`~/.claude/skills/...` はシンボリックリンク）。編集したらその場で commit＋push

## 進め方（必須）

1. **一次情報を集める**: 面談の文字起こし（Meet標準Transcriptを正）、案件KB、Notion面談ページ、相談で共有された資料。資料に書くのは、発言と既存資料にあることだけ
2. **前例の資料を見る**: 下の「素材と前例」。同じ業種・同じ論点の頁があれば流用する
3. **基ファイルは編集しない**: 深石さんに基ファイルの**複製**をお願いし、複製版のURLをもらってから作業する（Figma MCPに複製機能はない）。複製版では、使わない行（標準版・歯科医院向けなど）を消して、相手向けの1行だけにする
4. **構成案を出す**: 差し替える頁・足す頁・消す（非表示にする）頁を一覧にして、深石さんに見せてから作る
5. **作る → 自己チェック**（下の「仕上げのチェック」）→ スクリーンショットで深石さんに見せる
6. **PDFにする → 01_File_to に保存 → Driveの閲覧リンク**（下の「書き出しと共有」）
7. **送付メール**は `/email-draft` の「初回オンライン相談のお礼＋資料」の型で下書きまで。送信は深石さん
8. 送信を確認したら、Linear完了・KB更新ログ・`/nanco-status-update`
9. **指摘を受けたら、このファイルの「添削ログ」に追記**して commit＋push

## デザインの決まり（基ファイルの型）

- **フォント**: Inter（日本語もInter指定のまま）
- **見出し**: 基の頁の「Group 15」（Inter Bold 60px・#2C7873＋太さ12のティールの線）を**複製して使う**。位置 x88・y72。文字枠は `WIDTH_AND_HEIGHT` にして、線の長さ＝文字幅−20
- **見出し下の説明文**: Inter Regular 30px・黒・y190前後
- **カード**: #F2F2F2・角丸16。カードの見出しは Inter Bold 40px 前後・#1E4E4B
- **左右の余白は88px（中身の幅1744px）**。カードを横に並べる頁は、矢印と間隔の幅を引いてからカード幅を割る
- **頁番号**: 「スライド番号」は**ただの文字で、自動では振り直されない**（2026-10-20 デンケンで確認。頁を複製すると元の頁の番号のまま残り、get_screenshot でもそのまま出る）。頁を足したり並べ替えたら、最後に表示中の頁を順に数えて番号の文字を書き換える（非表示の頁は数えない・表紙から1）。**名前で探さない**: 頁によって名前が `Slide number`・`スライド番号`・空、位置も右下・ロゴの横とばらばら。「数字だけの文字で、頁の上端から990pxより下にあるもの」で探して直す（2026-10-20、名前で探して半分直し漏れた）
- **フッター**（ロゴ＋頁番号）は、基の頁のフッターのグループを複製する
- 扉の頁（ポイント◯）は基の扉を複製して文字だけ替える（バッジは SHAPE_WITH_TEXT の `.text`）

## 絵の使い方

- **装飾のイラストは入れない**。図解に入れる絵は「流れ・作業・機能」を表すもの（2026-10-19「イラスト追加が意味をなしていない。装飾はいらない」）
- **アイコン**: ティールの線アイコン（24マスのSVG・線1.6・#2C7873）を白い枠に入れ、下に短いラベル（Inter Bold 22px・ティール）。Figmaでは `figma.createNodeFromSvg()` で作れる。1つの頁の中は全部同じ形にそろえる
- **nancoを表すときはnancoのロゴ**（フッターのロゴを複製）。**「−＋」の記号は外して文字だけ**にする
- **人物イラスト**は、表紙・お悩み・nancoで解決のような「場面」の頁だけ（基ファイルの既存の絵を使う）
- **AI で描く絵は `/nanco-illust` で描く**（2026-10-20 深石さん指示）。既存の絵や線アイコンでは表せない「作業・機能」の絵が要るときだけ使う。Gemini・GPT Image・Figma の generate_image は使わない（2026-10-19 に試して、影が多いなどで基の絵柄に合わなかった）
  - 進め方: 頁ごとに「どんな絵を描くか（お題）」を構成案に書いて深石さんに見せる → nanco-illust で数枚描いて番号付きの一覧で見せる → 選ばれた絵の透過PNG（出力フォルダの `transparent/`）を `upload_assets` で差し込む
  - 上の「装飾の絵は入れない・流れ・作業・機能を表すもの」が優先。描けるからといって頁に足さない
  - 画面や紙の中の文字はでたらめになる。文字が要るところは Figma 側で重ねる
  - nanco-illust は Mac mini でだけ動く（MacBook からは remote-control で Mac mini のセッションを使う）
- **流れの図では、どこまでがnancoの中かを示す**（nancoの中の工程を薄いティールの枠で囲み、枠にnancoロゴ＋「の中でやること」。外側の工程の上に「取引先のシステム」「貴社のシステム」）

## 書き方の決まり

- **資料にあることだけ書く**（文字起こし・既存資料・KB）。未リリース機能（API・AI連携など）は時期を書かない
- **呼び方は私たちから見た言い方にそろえる**: 相手の会社＝「貴社」、相手の顧客（出荷指示を出す側など）＝「取引先」。「自社」「お客様」はどちらのことか読めないので使わない
- 相手が社内展開する資料なので、**相手にとって不利な事実**（納期遅延など）は載せない。相手の社内の役割分担にも踏み込まない
- 表紙: 「◯◯株式会社 御中」＋相手の用途に合わせたサブコピー1行（例「完成品の出荷と在庫を、スマホでかんたんに。」）。社名は本人が名乗ったものだけ
- お悩みの頁: 相手が面談で言った困りごとを3つ。見出しは1行に収まる長さ（10文字前後）
- 「ご相談のまとめ」を足すときの構成例: 扉→ご相談内容の整理（いまの状況／nancoでやりたいこと）→nancoを中間に置いた流れ→論点の選択肢（例: 管理部門の付け方A/B/C）→自動化の進め方と参考価格→次の進め方（品番リスト→登録→無料トライアル→打合せ＋予約URL）
- 確かめていないことは、頁の下に注記する（例「貴社のシステムの取り込み形式に合わせられるかは、CSVの仕様を拝見して確認します」）

## Figma操作の注意

- 別ファイルの頁は複製できない。**構造を読み出して組み直し、画像は get_screenshot で書き出して upload_assets で差し込む**。書き出した画像に元の枠線が入っているので、**外側に枠線を足さない**（二重枠になる）
- `figma.getSlideGrid()` は直前の `setSlideGrid` を反映していないことがある。並びは SLIDE_GRID ノードの子で確かめ、並べ替えは全行の順番を明示して指定する（2026-10-20 デンケンでも、続けて2回 setSlideGrid したら頁がばらばらに入った。最後に全頁のIDを並べて1回で指定し直し、SLIDE_ROW の子で一致を確かめた）
- フッターのロゴ（`Frame 3`）を `findAll` で探すと、カードの中に複製したロゴより先にフッターのものが当たる。親が GROUP かどうかで見分ける
- ファイル名はプラグインAPIで変えられない（`Setting the document name is currently not supported`）→ Claude in Chrome で Figma を開き、左上のファイル名をダブルクリックして変える
- 生成画像（generate_image）はスライドの外のキャンバスに置かれる。使わなかったら消す

## 書き出しと共有

1. 表示中の頁を `get_screenshot`（maxDimension 1920）で1枚ずつPNGにする（URLは短命なのですぐ curl）
2. PIL で PDF（quality=95・subsampling=0）にまとめ、pypdf で予約URLなどにリンク注釈を付ける（スクリプト例は下）。**文字は画像なので選択できない**ことを報告に書く
3. `01_File_to/nancoご紹介資料_<社名>様.pdf` に保存。**作り直すときは `cat new.pdf > 既存ファイル` で上書き**するとDriveのファイルIDが変わらず、送ったリンクがそのまま使える
4. Driveの共有を「リンクを知っている全員・閲覧者」にする: Driveコネクタの share_file では設定できないので、agent-browser（`--profile "$HOME/.agent-browser/profiles/gmail"`）で共有ダイアログ→一般的なアクセス→リンクを知っている全員
5. 確認: `get_file_permissions` に anyone/reader があること、未ログインの `curl "https://drive.google.com/uc?export=download&id=<ID>&confirm=t"` がローカルとバイト一致すること

```python
# build_pdf.py <PNGフォルダ> <出力PDF>  （p01.png〜の順）
import sys, glob, os
from PIL import Image
from pypdf import PdfReader, PdfWriter
from pypdf.annotations import Link
src, out = sys.argv[1], sys.argv[2]
imgs=[Image.open(f).convert("RGB") for f in sorted(glob.glob(src+"/p*.png"))]
tmp=out+".tmp.pdf"; imgs[0].save(tmp,"PDF",resolution=72,save_all=True,append_images=imgs[1:],quality=95,subsampling=0)
r=PdfReader(tmp); w=PdfWriter(); [w.add_page(p) for p in r.pages]
# リンク: rect は PDF座標（左下原点・1920x1080pt）。上端y_topの文字なら (x0, 1080-y_bottom, x1, 1080-y_top)
w.add_annotation(page_number=24, annotation=Link(rect=(88,1080-926,730,1080-878), url="https://www.nanco.io/free-consultation"))
w.write(open(out,"wb")); os.remove(tmp)
```
