# nanco-meeting-prep — 打合せ準備（Notion面談ページ）

nanco顧客・レディクル案件の打合せ準備は、**Notionの面談ページ作成までが1セット**（2026-07-27 深石さん「毎回、nancoカスタマーの準備はnotionページまで準備してほしい」）。
この文脈でのNotionページ作成は**事前承認済み**。それ以外のNotion書き込み（列の追加・削除、他人のページの編集など）は従来どおり承認を取る。

## 1. どちらのDBに作るか

| 相手 | 置き場所 | ページ名 |
|---|---|---|
| nanco顧客（予約フォーム・HubSpot・既存顧客） | 「nanco営業データ」DB `collection://1be60519-c341-4ee2-8c68-9db180f003ca` | `YYMMDD_nanco_会社名`（社名が未確認なら `YYMMDD_nanco_氏名さん`） |
| レディクル案件（まだ受託かnancoか決まっていない） | PROJECTS › Project DB `collection://6f5e4594-0a35-4b70-af4e-d0764508ff9d` の親ページ `26xx_会社名` › その中の「MTG・議事録」DB | `YYMMDD_[レディクル]会社名` |

- **レディクル経由でも、nanco導入（トライアル・nanco契約）に進んだ顧客は nanco営業データ側**（2026-10-15 深石さん「タムラはnanco関連」）。過去の面談ページが26xx_親ページ配下にあっても踏襲しない
- 迷ったら、Customers DB の行の「利用状況」（ベータ版・利用中ならnanco）と、相手がワークスペースを持っているかで判断する

### nanco営業データのプロパティ
- Name／Status=`Not started`／`date:At:start`=会議日（`date:At:is_datetime`=0）
- 🫂 Customers=Customers DB（`collection://842d7d57-058d-4df8-a229-9cea0a2eadaf`）の該当行。行が無ければ作成は深石さんに提案（`/nanco-status-update` の「行が無いとき」に従う）

### レディクルの親ページ（無いときだけ作る）
1. Project データソースに `template_id: 03cbc99061734d889f3200f99402728c` 付きで作成。Name=`26xx_会社名`、Tag=`["新案件","フロンティア"]`、ステータス=`WAIT`
2. 作った親ページを fetch → 「MTG・議事録」のブロックIDを fetch して、**その親ページ専用の** MTG・議事録データソースID（`collection://…`）を取る（テンプレートのコピー直後は `copy_indicator` と出るが、ブロックIDを直接 fetch すれば取れる）
3. そのデータソースに面談ページを作る。日付は `date:Date:start`

## 2. 材料集め（読み取りだけ）

社ごとに次を全部見る。件数が多い日は社ごとにエージェントを並列で走らせ、**読み取りだけ**させてファイルに書き出させる（書き込みは呼び出し元でやる）。

- **顧客フォルダ**（共有ドライブ Nanco/カスタマー/会社名/）: KB（02_Plan）、06_Recording の文字起こし**全文**（要約は根拠にしない）、00_File_from の資料

- **Linear**（team `nanco`）: 会社名を含むイシューの状態。前回こちらが約束した件の進み具合
- **nanco管理画面** `https://app.nanco.io/admin/workspaces?search=<社名>`: ワークスペースの有無・トライアル期限（Next Date）・アイテム数・ユーザー数・最終操作。プランの上限（1,500／5,000）に近ければ注意点に書く。agent-browser の gmail プロファイルは nanco 未ログイン。実Chrome（claude-in-chrome）なら管理者セッションで読める（初回はダッシュボードに飛ぶので同じURLを開き直す）

- **レディクル**: rc_support@frontier-gr.jp の案件紹介・アポ確定・リマインドメール本文。報告書PDFは Drive「レディクル」フォルダ（id `1YOEC5feS3SIv8FHhiX6w0afcmwod3ctJ`）にあれば読む。報告書メールの「URL」は当社の日程調整ページのことがある（Meetとは別）ので注意

## 3. ページの構成

1. **思い出しメモ（必須・2026-10-15〜）**: 冒頭に 💡 callout（`color="yellow_bg"`）で3〜5行。中身は次の4つで、一次情報にあることだけ書く
   - どんな会社か（所在地・業種・規模）
   - いちばんの要望（何がしたいか）
   - どこまで進んでいるか（WS・トライアル期限・前回決まったこと）
   - 残っている宿題（こちら・先方）
   - 情報がほとんど無い初回でも省略しない（「事前のやりとりなし＝ゼロからヒアリング」のように短く書く）
2. 相手の名前・メール・前回ページ／Customers行へのリンク
3. 事前情報（表: 日時／Meet／出席／予約経路／WSの状況／注意点）
4. 前回からの経緯（日付つき。根拠はメール件名や文字起こし）
5. 先方の質問・要望の原文（引用）
6. （既存顧客なら）こちらの約束と現状（Linear番号つきの表）
7. アジェンダ案（60分。次の予定があるなら「◯時厳守」）
8. 論点・質問表（`| 論点 | 確認したいこと | 当日メモ |`、当日メモは空欄）
9. 料金・当日の材料（資料にある数字だけ）
10. 当日メモ（現状確認／決定事項／宿題／次回）。レディクルはアクションアイテム表も
11. 未確認事項

書き方の注意:
- 推測は「推定」、確かめていないことは「未確認」。社名は相手が名乗った表記を使い、メールドメインから推定した社名は「推定」と書く
- Notion内の他ページは `<mention-page url="…"/>` で参照する。**リンク文字列に `[ ]` を含むMarkdownリンクは崩れる**（`[261007_[レディクル]…](…)` で実発生）
- メールアドレスを全角括弧で囲むと mailto のリンクが崩れる
- 作ったら fetch で読み直し、表・callout・リンクが崩れていないか確かめる

## 4. やってはいけないこと
- **別DBのページを move-pages でnanco営業データに移さない**。元DBの列（例「Date」）がnanco営業データにくっついて増える（2026-10-15 実発生→ DROP COLUMN で戻した）。置き場所を間違えたら作り直す。どうしても移したら、移した直後にスキーマを確認する
- 列の追加・削除・選択肢の変更は、深石さんの承認を取ってから
