# zaico→nanco 増分移行（そら植物園）

そらは新規植物をzaicoに登録し続けており、たまったら「N####〜N####を写真付きで移行して」とLINEで依頼が来る（定型・繰り返し案件）。実働30〜45分/50件規模。

## 環境・道具（前提）

- **zaico**: web.zaico.co.jp・そら植物園株式会社・フルプラン。ログインは実Chrome（1Password「そら植物園在庫」）→ agent-browser `--profile Default` で再利用。**APIトークンはアカウント設定画面（ユーザー「仕入れ２」）に常時表示**（再生成ボタンは押さない）
- **nanco本番**: `app.nanco.io/kZfEOK`（そら植物園）／テスト: `app.nanco.io/GloL-DSaWg`（8/4本番コピー・アイテム数無制限・別ワークスペース）。どちらも実Chromeログイン済み
- **nanco MCPの接続先はGSIテスト環境**（`GSI_棚卸しテスト_2607`/HP0AOV・OAuth）。そら本番には繋がっていないので既定は**全部agent-browser**（`--profile Default`を全コマンドに）
  - 大量件数・面倒な依頼が来たら**MCPをそら本番へ繋ぎ替えるのを検討**（過去にOAuthでkZfEOKに接続した実績あり）。`bulk_create_items`ならデータ＋属性（N番号・キーワード・備考）を1コールで登録でき、**一時フォルダ方式もフォルダ移動も不要**（目的フォルダに直接作成。「複数候補」判定はCSVインポート特有の問題）＝データ工程の約9分がほぼゼロになる
  - ⚠トレードオフ: MCPは本番へ直接書き込みでCSVインポートの**プレビュー安全弁（新規N件/複数候補0件）が無い**。一時フォルダに作成→API検証→移動、で担保する
  - ⚠**写真はMCP不可**（ext/v1に画像アップロード口が無い・NANCO-1640がIn Review）。**NANCO-1640がDoneになったら要確認**＝URL指定方式（zaicoのS3 URLをそのまま渡す）が入れば写真工程11分も消えて全体が実質数分になる
- 大きい依頼・手順変更があれば先にテスト環境でリハーサル（初回は全工程リハ済みなので、同型の依頼なら本番直行でよい）

## 受領時にやること

1. **顧客に確認2点**（過去に思い込みで外した実績あり・必ず聞く）: ①登録先フォルダ（例: 03_落葉と思ったら「14_入荷前」だった） ②キーワードの値（例: 全件「モミジ/カエデ」指定）。返信はOA「nancoサポート」のWebチャット chat.line.biz から深石さんが送る（引用リプライ可）
2. Linear起票（`[そら植物園][データ移行] zaico N####〜N#### …`・原文転記・No priority・NANCO-1982の型を踏襲）

## Phase 0: 事前チェック（本番・読み取りのみ）

- プラン画面 `kZfEOK/settings/plan`: **アイテム数の空き**（5,000上限・2026-08-13時点で4,840）と**画像ストレージの空き**（100GB上限。**超過中は写真アップが「ストレージ容量を超過します/空き容量(0B)」で全拒否される**→先に姉崎さんに容量対応を依頼。データ投入だけ先行し写真は後追い可）
- 対象N番号の不在確認（検索スポット＋後述エクスポートで全数確定）
- **直前バックアップ**: home→ダウンロード→Excelファイルとしてダウンロード。⚠**ダウンロード完了まで10秒待ってから最新ファイルを掴む**（8MB級はレースで古いファイルを拾う事故あり）。`ls -t ~/Downloads/在庫一覧*.xlsx | head -1`

## Phase 1: zaico抽出

```bash
TOKEN=<zaico設定画面から>  # チャットログに残して良いか毎回配慮
curl -s -H "Authorization: Bearer $TOKEN" "https://web.zaico.co.jp/api/v1/inventories?page=N"
# 1000件/頁・id昇順・link/total-countヘッダー。新しいアイテムは最終頁側
```

- 対象抽出: `optional_attributes` の `N番号` でレンジフィルタ → 件数・欠番・枝番(-A/-B)・数量合計を確定
- **写真**: `item_image.url`（S3・認証なしDL可）。⚠**URLの%2Fをデコードすると403**＝生のまま使う。`photos/<N番号>.jpg` で保存し枚数・サイズ検証
- **組み込み項目も必ず見る**: `etc`(備考・初回で移行漏れしかけた)・`place`・`state`・`group_tag`・`unit`。`code`(tw…)はzaico内部コードで移行不要（初回移行も持ち込んでいない）
- zaicoのカテゴリ→nancoはフォルダで表現（属性なし）。検索系3属性のうち**zaico画面に出るのは検索別キーワードのみ**（残り2つは隠れ属性）→ キーワードは顧客指定値を使う

## Phase 2: 変換CSV

列: `フォルダ1, アイテム名, 在庫数, 樹高（鉢上）m, 仕入単価, 仕入れ先, キーワード, 備考`

- **フォルダ1=一時フォルダ名**（例 `99_zaico移行_YYMMDD`）に全行統一 ＝ **同名既存アイテムとの「複数候補」判定を構造的にゼロにする**ための方式。顧客指定フォルダへは最後に一括移動
- **nancoID列は絶対に入れない**（nanco内部ID N0000123形式でそらのN番号と別物。入れると既存上書き事故）。N番号もCSVに入れない（専用欄=商品識別コードはCSVで入らずカスタム属性が生えるだけ）
- 在庫数は整数化。空値は空のまま（創作しない）。キーワード・備考は顧客指定/zaico実値
- ヘッダー20文字以内・セル191文字以内・3,000行以内

## Phase 3: インポート（本番）

home → 作成 → **一括アイテム登録** → CSVアップ → 次へ → **プレビューが「新規N件・複数候補0件・N/N件選択中」であることを必ず確認してから**「一括登録」→「すべてのデータが登録済みです」→ プラン画面でアイテム数が+Nちょうどを検証

- プレビューは本番だと描画に10秒以上かかることがある（ポーリング）
- 複数候補が出たら中断して原因確認（一時フォルダ方式なら出ないはず）。行ごとの「新規アイテムとして登録」ポップオーバーは自動操作でウィザードごと閉じる不具合があり当てにしない
- 既存アイテムの一括修正には**nancoID照合の更新インポート**が使える（列=nancoID+アイテム名+修正列。プレビューが「更新: N件」になる）

## Phase 4: 写真＋N番号（1件13秒）

フォルダページから `a[href*="/item/"]` をスクロール収集→各アイテムページで:

1. `upload "input[type=file]" photos/<N>.jpg`（**オリジナル画質チェックは入れない**＝既存と同じ`_nanco_medium`600px級になる）
2. N番号欄: 値セルに**実マウスhover→出現したtextareaにfill→隣の確定ボタンをクリック**（Enter・JSイベントでは保存されない）
3. **アップロード開始から10秒待ってから次ページへ**（早く遷移すると写真が静かに消える。初回44/49消失の教訓）

同名アイテムへの割当は `scripts/resolve.py`（属性シグネチャごとのキューでN番号を一意配布。写真とN番号のペアが崩れない）。worker/sweepの雛形は `scripts/` 参照（ワークスペースIDを書き換えて使う）。

## Phase 5: 検証（4層・全部やる）

1. **エクスポート突合**: 本番エクスポート→対象行×9項目（名・数・樹高・単価・仕入先・キーワード・備考・販売価格空・重量空）をzaico生JSONと突合＝**差分ゼロ必須**。あわせて**Codexにも生データ2ファイル＋変換仕様だけ渡して独立突合**させ結論一致を確認（`codex exec --sandbox read-only --skip-git-repo-check`）
2. **表示スイープ**: 全件をページで開き直し「画像が実表示(naturalWidth>0)・N番号一致」（blobプレビューに騙されない・リロード後が正）
3. **照合シート＋自分の目視**: agent-browser v0.34+ `set viewport 1280 3400`→素の`screenshot`（--fullは内部スクロールUIに無効）でzaico/nanco各1枚→横並びJPG合成→全件目視（自分＋並列レビューエージェント分担）。シートはHTML(base64埋込)で深石さんにも渡す
4. **Codexセカンドオピニオン目視（必須）**: 照合ペア画像を10枚/バッチで `codex exec -i pairs/pair_N####.jpg ... "<期待値表付き検証プロンプト>"` → 全件OK/NG判定を取得。**自系（Claude）と別ベンダーの両方がOKして初めて完了扱い**

## Phase 6: 配置・清掃

- 全選択（「表示中のすべてを選択」）→移動→移動先ツリーで顧客指定フォルダ→**「数量を入力」→「移動する」**（ダイアログ内ボタンはJSクリックが確実。ホバー被りで実マウスは失敗しがち）→「移動しました」確認
- 一時フォルダが空（合計0）を確認して削除（フォルダカードのメニューは「メニューを開く」ボタン＝**innerTextマッチ・実マウスクリック**でないと開かない）

## Phase 7: 報告

- **LINE完了報告**（文案→深石さん承認→chat.line.bizから送信）。LINEなので「お世話になります/ひきつづき〜」の挨拶・締めは入れない。件数・フォルダ・キーワードを明記
- Linear: 経過/完了コメント（一次情報主義・エラー原文・検証結果・成果物パス）→ Done
- KB（そら植物園様_総合AIプロファイル.md）に【YYMMDD更新】追記（pythonで・バックアップ後）
- 作業データ（写真・生JSON・突合レポート・照合シート・前後バックアップ）は `カスタマー/そら植物園/zaico移行_YYMMDD_作業データ/` へ退避

## 既知の罠（初回で全部踏んだ）

| 罠 | 対策 |
|---|---|
| 写真アップ後すぐ遷移で消える | 10秒待ち厳守・最後に全件表示検証 |
| blobプレビュー＝保存済みではない | リロード後のnaturalWidth>0で判定 |
| ストレージ超過中は全アップ拒否 | Phase 0で空き確認・超過時はデータのみ先行+姉崎さん依頼 |
| エクスポートDLのレース | 10秒待ち+ファイルサイズ/行数検証 |
| 検索・プレビューの描画遅延 | 「結果がありません」等は数秒待って再読・ポーリング |
| eval内の正規表現がシェルで壊れる | `\n`入り文字クラス禁止・indexOf/includes方式に逃がす |
| refはスナップショット毎に振り直し | 取得→即クリック・再レンダー後は取り直し |
| ホバー出現UI（N番号欄・カードメニュー） | 要素にid付与→実マウスhover/click。JSクリックはRadixドロップダウンに無効 |
| 一覧サムネの欠けは遅延描画 | 写真有無の判定は詳細ページ/APIで |
| ブラウザセッションが壊れる(ERR_BLOCKED_BY_CLIENT等) | `agent-browser close --all`→開き直しで復旧 |

## 実測（2026-08-13・49件72本）

インポート22秒／UUID収集15秒／写真+N番号13.2秒/件（49件=10分46秒）／表示スイープ5分／照合シート撮影〜生成12分／Codex目視7分。**合計約35分＋顧客往復**。
